# Proposal

## Why

Agent 制定多步计划时，可能没有记下后续哪个决定需要查 Practice。用一条短规划提示把具体检索问题留在相关步骤，不把 Skill 写成全生命周期手册。

## What Changes

- 新增模型指引：Agent 已在列计划时，把相关后续步骤需要查的具体问题写在该步骤；到步骤时按需 `lore query`，用 `lore get` 读全文，在用户授权范围内应用。
- 保留已有任务和状态，不为 Lorelum 单独创建或重置计划。没有计划时仍可按现有方式查询；不要求给既有计划补写提醒，不规定计划文档或交接等备用载体。
- omp 插件保存待查问题，即使重建计划遗漏也会把未关闭的提醒交回模型。沿用 CLI 查询和读取接口。

## 产品说明

用户照常提出多步任务，不需要写 Practice ID。例如，Agent 先交付项目清单，再设计导入验收用例；如果它本来就要列 todo，验收步骤可写为「设计 CSV 验收用例前，查非数字数量的拒绝行号和错误码约定」。完成清单后，omp 的 todo 工具结果可以把后续事项交回模型。进入验收时，Agent 按需检索和阅读，再把适用的行号与错误码写入验收 JSON。不是用户操作 todo 就会自动查询。

在 omp 中，Agent 可在步骤中写 `[practice: 拒绝行用哪个错误码？]`。插件返回带编号的提醒，例如 `P1: 拒绝行用哪个错误码？`。用户要求合并计划时，即使新列表只剩「完成验收」，模型仍会收到 `P1`。处理后由 Agent 关闭该编号。用户也可以要求撤销指定提醒。

已有计划照常推进，没有计划仍可按需查询。未登记的问题依赖 Agent 主动查阅。查询失败沿用现有恢复合同，未处理的提醒继续保留。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `agent-integration`：Skill 引导 Agent 在规划时为相关步骤留下具体检索问题，并复用已有的查询与全文读取机制；Catalog 增量仅澄清已有发现路径与已知 ID 直读的区别。

## Impact

共享 Skill、宿主生成文件、omp 扩展与双语接入说明。提醒保留和按编号关闭由 omp 提供。
